Section 1 — Daily Sales Operations
Use Cases UC-01 through UC-08 — Cashier & POS counter scenarios
UC-01
Daily Opening: Open Shift & Start Selling
Cashier Admin
Trigger
Cashier arrives at start of their working day
Frequency
Every working day, per cashier
Precondition
Cashier has an active system account

Main Flow

  1. Cashier logs in with username and password at /login
  2. Navigated to POS Terminal. System prompts: "No active shift found. Please open a shift to continue."
  3. Cashier goes to Shifts → clicks Open Shift
  4. Counts the opening float (cash in the till) and enters the amount (e.g. PKR 5,000)
  5. Clicks Open — shift is now active with a timestamp
  6. Returns to POS Terminal — system is ready to process sales
Outcomes
Shift is open and linked to this cashier's user account
All sales processed will be recorded under this shift
Opening float is recorded — used for end-of-day cash reconciliation
/login/pos/shifts/
UC-02
Complete a Cash Sale
Cashier
Trigger
Customer brings goods to the counter
Frequency
Dozens to hundreds of times per day
Precondition
Shift is open. Products exist in system with stock > 0

Main Flow

  1. Cashier scans the product barcode (or types name in search box and presses Enter)
  2. Product appears in cart with quantity 1. Repeat for all items
  3. Adjust quantities using + / − buttons if customer wants more of the same item
  4. Select payment method: Cash
  5. Enter the amount the customer hands over (e.g. PKR 1,000)
  6. System calculates and displays change due (e.g. PKR 235)
  7. Click CHARGE
  8. Receipt is generated — give change and receipt to customer
⚡ Alternate: Product not found
If a barcode scan returns no result, the product is not in the system. Cashier must check with a manager. Do not manually key in a price without a product record.
Outcomes
Sale recorded, receipt generated with unique receipt number
Stock automatically reduced for each item sold
Journal entry posted to Finance: Cash Dr / Sales Revenue Cr
Shift total updated with this sale amount

UC-03
Complete a Card / Mobile Wallet Sale
Cashier
Trigger
Customer pays by card or mobile wallet
Precondition
Shift is open

Main Flow

  1. Add products to cart as normal
  2. Select payment method: Card, EasyPaisa, JazzCash, UBL, or Meezan
  3. Process the card/wallet payment on the physical terminal or mobile
  4. Once payment is confirmed by the bank/wallet, click CHARGE in the system
  5. Receipt is generated — no cash change is given
💡 For split payments (e.g. PKR 500 cash + PKR 300 card), select Split Payment and enter the amount for each method.

UC-04
Apply Discount & Promo Code
Cashier
Trigger
Customer has a promo code or manager authorizes a discount

Discount Types

  1. Product Discount: Already built into the product price (set in Products page). Applied automatically — no cashier action needed
  2. Cart Discount %: Enter a percentage in the "Cart Discount" field (e.g. 10% off total). Requires manager authorization for amounts above store policy
  3. Promo Code: Customer provides a code. Enter it in the Promo Code field and press Apply. System validates and shows the discount amount
  4. Loyalty Points: If customer has points, cashier selects them and system applies the equivalent PKR value as a deduction
Outcomes
Discount applied and shown on receipt with original and discounted price
Discount amount is tracked in reports for management review
/
UC-05
Sell to a Loyalty Customer & Earn Points
Cashier
Trigger
Regular customer wants to earn or redeem loyalty points

Main Flow

  1. Add items to cart as normal
  2. In the Customer field, search by name or phone number
  3. Select the customer — their current loyalty points balance is shown
  4. To earn points: Complete the sale normally — points are added automatically
  5. To redeem points: Toggle "Use Loyalty Points" — system shows PKR value and deducts from total
  6. Click CHARGE — receipt shows points earned and new balance
//pos/customers
UC-06
Process a Sales Return / Refund
CashierAdmin
Trigger
Customer returns a product after purchase
Precondition
Original sale exists in system

Main Flow

  1. Go to Sales Returns /pos/returns
  2. Search for the original sale by receipt number or date
  3. Select the items being returned and enter quantities
  4. Select return reason from dropdown: Defective / Wrong Item / Customer Changed Mind / Other
  5. Select refund method (Cash or Reverse to original payment)
  6. Click Process Return
Outcomes
Return recorded with unique Return ID and timestamp
Stock restored for returned items
Refund amount recorded in Sales Returns report
Loyalty points earned on original sale are reversed if applicable
⚡ Alternate: Receipt not available
Customer cannot provide receipt. Cashier searches by date and approximate amount. Manager must authorize the return before proceeding.
/pos/returns
UC-07
Record a Credit Sale (On Account)
CashierAdmin
Trigger
Trusted customer wants goods now, will pay later
Precondition
Customer is registered in system. Manager approval required

Main Flow

  1. Add items to cart and select the customer
  2. Choose payment method: Credit / On Account
  3. Manager approves and cashier clicks CHARGE
  4. Sale is recorded — invoice shows as outstanding in Credit Sales
  5. When customer pays later: go to Credit Sales → find the customer → record payment
⚠️ Only extend credit to known, registered customers. Always get manager sign-off. Monitor balances weekly via the Credit Sales report.

UC-08
Close Shift & End of Day Report
CashierAdmin
Trigger
Cashier finishes their working day
Frequency
End of each cashier shift

Main Flow

  1. Count all cash in the till physically
  2. Go to Shifts → click Close Shift
  3. Enter the actual closing cash amount (physical count)
  4. System compares: Expected Cash = Opening Float + Cash Sales − Cash Refunds
  5. Any difference is flagged as Over or Short — must be explained
  6. Go to Z-Report → print or save the end-of-day summary
  7. Manager reviews and signs off the Z-Report
Outcomes
Shift closed — no more sales can be processed until next shift is opened
Z-Report shows total sales, payment breakdown, discounts, taxes
Daily accounting record is complete
/pos/shifts/z-report

Section 2 — Inventory Management
Use Cases UC-09 through UC-12 — Products & stock scenarios
UC-09
Add a New Product to the System
AdminProcurement
Trigger
New product being introduced for sale
Precondition
Product details (price, barcode) available

Main Flow

  1. Go to Products → click Add Product
  2. Enter product name, category, supplier, barcode (scan or type)
  3. Enter selling price, cost price, and MRP
  4. Enter initial stock quantity and set reorder level
  5. If perishable, enter expiry date
  6. Click Save — product is immediately available at POS counter
Outcomes
Product appears in POS search and barcode scanner lookup
Product appears in all inventory reports
If stock is at or below reorder level, it will appear in Reorder Alert report immediately
/products
UC-10
Bulk Import Products via Excel
Admin
Trigger
Large number of products to add at once

Main Flow

  1. Go to Products → click Download Import Template
  2. Open the downloaded Excel file and fill in product data row by row
  3. Save the Excel file
  4. Back in Products, click Import Excel and upload your file
  5. System validates the file — any errors are shown with row numbers
  6. Fix errors, re-upload if needed, then confirm import
💡 Always use the downloaded template. Do not change column headers — the system requires them to be exactly as provided.
/products
UC-11
Adjust Stock After Physical Count
AdminProcurement
Trigger
Monthly physical stock count reveals discrepancy
Frequency
Monthly or after any suspected theft/loss

Main Flow

  1. Run Stock Report from Reports Center — shows system stock for each product
  2. Perform physical count of actual items on shelf and in warehouse
  3. Identify items where physical count ≠ system stock
  4. Go to Stock Adjustments → click New Adjustment
  5. Search for the product, enter the adjustment quantity (+ or −)
  6. Select reason: Count Correction / Damaged / Theft / Other
  7. Add a note and click Save
Outcomes
Stock corrected to match physical reality
Adjustment logged in Audit Trail with user, date, time and reason
/inventory/adjustments/reports/stock-report
UC-12
Handle Damaged or Expired Stock
AdminProcurement
Trigger
Products found damaged or past expiry date

Main Flow

  1. Run Expiry Report to identify products expired or expiring within 30 days
  2. Physically remove the products from shelves
  3. Go to Stock Adjustments → create a negative adjustment
  4. Enter quantity to remove and select reason: Expired or Damaged
  5. Document the write-off for insurance or vendor claim purposes
  6. If vendor is responsible for damaged goods, raise a claim through Vendor Invoices
/reports/expiry-report/inventory/adjustments

Section 3 — Procurement Workflow
Use Cases UC-13 through UC-17 — End-to-end buying process
UC-13
Add a New Vendor / Supplier
ProcurementAdmin
Trigger
New supplier relationship being established
Precondition
Vendor details and payment terms agreed

Main Flow

  1. Go to Procurement → Vendors → click Add Vendor
  2. Enter vendor name, contact person, phone, email, address
  3. Enter payment terms (e.g. Net 30 days) — this feeds Invoice Aging report

Vendor available for selection when creating Purchase Orders
Vendor appears in Vendor Reliability Score in Predictive Dashboard

UC-14
Raise a Purchase Requisition (PR)
Procurement
Trigger
Products are running low or new stock needed

Main Flow

  1. Check Reorder Alert Report to identify what needs ordering
  2. Go to Procurement → Purchase Requisitions → click New PR
  3. Select the vendor and fill in required items with quantities needed
  4. Add any notes or urgency level
  5. Submit PR — status becomes Pending Approval
  6. Manager receives the PR and reviews it
💡 The Reorder Alert report at /reports/reorder-alert is your starting point — it tells you exactly which products and how many to order.
/reports/reorder-alert/procurement/pr
UC-15
Approve a PR & Create a Purchase Order
AdminProcurement
Trigger
A Purchase Requisition is pending approval

Main Flow

  1. Go to Purchase Requisitions → find the pending PR
  2. Review items, quantities and vendor — modify if needed
  3. Click Approve & Convert to PO
  4. A Purchase Order is created automatically with a PO number
  5. PO status is Approved — print or email it to the vendor

UC-16
Receive Goods & Update Stock (Goods Receipt)
Procurement
Trigger
Vendor delivers goods to the store
Precondition
A Purchase Order exists for this vendor

Main Flow

  1. Vendor arrives with goods and delivery note
  2. Go to Goods Receipt → click New GR
  3. Select the PO this delivery is against
  4. System shows ordered quantities — enter actually received quantities for each item
  5. Note any shortages, damage or substitutions
  6. Click Save GR — stock is updated immediately for received items
  7. A vendor invoice is generated automatically for the received amount
Outcomes
Stock increased for received items — immediately available at POS
PO status updated to Received or Partially Received
Vendor invoice created — visible in Vendor Invoices for payment
/procurement/gr/procurement/invoices
UC-17
Pay a Vendor Invoice
AdminProcurement
Trigger
Invoice payment is due or management decides to pay

Main Flow

  1. Check Invoice Aging Report to see overdue or upcoming invoices
  2. Go to Vendor Payments → click Record Payment
  3. Select the vendor invoice being paid
  4. Enter the payment amount, date and method (bank transfer, cheque, cash)
  5. Click Save — invoice status updates to Paid or Partial
💡 Run the Invoice Aging report weekly to catch invoices approaching 60+ days. Late payments damage vendor relationships and may attract penalties.
/reports/invoice-aging/procurement/payments

Section 4 — HR & Finance
Use Cases UC-18 through UC-19 — Employees and payroll
UC-18
Add a New Employee
Admin
Trigger
New staff member joins the business

Main Flow

  1. Go to HR Dashboard → click Add Employee
  2. Enter name, CNIC, department, designation, join date
  3. Enter salary structure: basic salary, allowances (transport, housing), deductions (EOBI, tax)
  4. Click Save — Employee ID is auto-generated (EMP-001)
  5. Create a system user account for them if they need to log in (separate step in System Users)
/hr/admin/users
UC-19
Process Monthly Payroll
Admin
Trigger
End of month — salaries due
Frequency
Monthly

Main Flow

  1. Go to HR Dashboard → click Process Payroll
  2. Select the payroll month (e.g. May 2026)
  3. System auto-fills salary data for all active employees from their profile
  4. Review and adjust for any one-off additions or deductions
  5. Click Generate Payroll — payroll records created for each employee
  6. Export to Excel for bank transfer instructions
  7. Once salaries are paid, mark payroll as Paid
Outcomes
Payroll records created — visible in Payroll Summary report
Payroll expense posted to Finance GL automatically
Appears in Profit & Loss report under Payroll expense for the month

Section 5 — Reports & Analysis
Use Cases UC-20 through UC-26 — Management reporting and AI insights
UC-20
Run a Sales Report & Export to Excel
AdminSales
Trigger
Manager wants to review last week's or last month's sales

Main Flow

  1. Go to Reports Center → Sales Reports section
  2. Click View on Sales Report
  3. In the filter bar, enter date range (From / To)
  4. Optionally filter by payment method (e.g. Cash only)
  5. Click Apply — KPI cards show totals instantly (revenue, transactions, taxes, discounts)
  6. Use the search bar to find specific cashiers or customers within the results
  7. Click Download Excel — real .xlsx file downloads immediately
  8. Open in Excel for further analysis or send to accountant
/reports/reports/sales-report
UC-21
Identify Best-Selling Products & Boost Strategy
AdminSales
Trigger
Monthly business review meeting

Main Flow

  1. Go to Reports → Sales by Product
  2. Set date range (e.g. last 30 days)
  3. Products are ranked by revenue — top performers at the top
  4. Review margin % for each product — low margin products may need price adjustment
  5. For AI-powered product insights, go to Predictive Analysis → Sales
  6. AI shows top 10 products, projected growth and which items to push more
💡 Products with high revenue but low margin are volume plays. Products with high margin but low revenue need better promotion. The AI dashboard highlights both.
/reports/sales-by-product/admin/predictive/sales
UC-22
Find Products That Need Reordering
ProcurementAdmin
Trigger
Weekly procurement review
Frequency
Weekly recommended

Main Flow

  1. Go to Reports → Reorder Alert
  2. Report shows all products at or below reorder level, color-coded by urgency
  3. Red = Out of Stock (order immediately), Orange = Critical (<50%), Blue = Low
  4. Export to Excel and use it as the basis for raising Purchase Requisitions
  5. Create PRs in Procurement for the required items
Outcomes
Never run out of stock unexpectedly — proactive reordering
Report refreshes live — run it any time, not just weekly
/reports/reorder-alert/procurement/pr
UC-23
Review Profit & Loss for the Month
Admin
Trigger
End of month financial review
Frequency
Monthly

Main Flow

  1. Go to Reports → Profit & Loss
  2. Report shows last 24 months of Revenue, Purchases, Payroll, Net Profit and Margin %
  3. Identify months with low margin — investigate cause (high returns, promotions, high procurement cost)
  4. Export to Excel for your accountant
  5. For deeper analysis, go to Predictive Analysis → Finance for 6-month profit forecast
💡 A healthy retail margin is typically 15–25%. If your margin drops below 10% for two consecutive months, review your pricing and procurement costs urgently.
/reports/profit-loss/admin/predictive/finance
UC-24
Check Vendor Invoice Aging & Pay Overdue Bills
AdminProcurement
Trigger
Weekly accounts payable review

Main Flow

  1. Go to Reports → Invoice Aging
  2. Invoices are bucketed: 0-30 days (green), 31-60 (blue), 61-90 (yellow), 90+ (red)
  3. Focus on red bucket first — these are the most overdue
  4. Export list and prioritize payments based on vendor terms and relationships
  5. Go to Vendor Payments and record payments for prioritized invoices

UC-25
View AI Business Health Score
Admin
Trigger
Weekly or monthly management review

Main Flow

  1. Go to Admin Dashboard → click the purple Predictive Analysis banner
  2. The Overview tab loads with a Business Health Score out of 100
  3. Score is calculated from 4 components: Sales trend (25pts), Procurement efficiency (25pts), Profit margin (25pts), Vendor reliability (25pts)
  4. Read the color-coded AI Insight cards at the bottom: Green = Good, Orange = Watch, Red = Act now
  5. Drill into specific tabs (Sales, Finance, etc.) for more detail
💡 Aim for a Health Score above 70. A score below 50 means at least two major areas of the business need urgent attention.
/admin/predictive
UC-26
Forecast Next 6 Months of Revenue
Admin
Trigger
Planning budget, stock levels, or expansion

Main Flow

  1. Go to Predictive Analysis → Sales
  2. The Revenue Forecast chart shows historical data (solid line) and 6-month AI prediction (dashed line)
  3. Review the trend: Is revenue growing, flat, or declining?
  4. Go to Predictive Analysis → Finance for profit forecast
  5. Use these projections to plan: How much stock to order? Can we hire another staff member? Are we on track for the year?
💡 The AI predictions become more accurate as you have more months of data. The more you use the system, the better the forecasts.

Section 6 — System Administration
Use Cases UC-27 through UC-30 — Users, security and setup
UC-27
Create a New System User Account
Admin Only
Trigger
New staff member needs system access

Main Flow

  1. Go to System Users → click Add User
  2. Enter username (no spaces, e.g. ahmed_cashier), full name, email
  3. Set a temporary password — tell the user to change it on first login
  4. Select their role: admin / cashier / sales_person / procurement_manager
  5. Click Save
⚡ Staff leaves the business
Go to System Users → find the user → click Deactivate. Do NOT delete the account — this preserves their sales history and audit records.
/admin/users
UC-28
Investigate a Suspicious Transaction
Admin Only
Trigger
Cash discrepancy, unusual refund, or suspected theft

Main Flow

  1. Go to Reports → Sales Report — filter by the cashier and date in question
  2. Look for unusual patterns: large discounts, multiple refunds, transactions with no product
  3. Go to Reports → Sales Returns — check all returns processed by that cashier
  4. Cross-reference with Audit Trail — see every action the user took with timestamps
  5. Compare Z-Report cash expected vs actual for that shift
  6. If fraud confirmed, deactivate the account and escalate as per company policy
🔴 The Audit Trail is tamper-proof. Every login, sale, return, stock adjustment and setting change is logged permanently.
/reports/sales-report/reports/sales-returns/audit-log
UC-29
Create a Product Bundle / Promotion
Admin
Trigger
Running a promotional deal (e.g. Eid Bundle, Family Pack)

Main Flow

  1. Go to Bundles → click Create Bundle
  2. Give the bundle a name (e.g. "Ramadan Family Pack")
  3. Add the products included in the bundle with their quantities
  4. Set the bundle price (typically lower than buying individual items)
  5. Set an optional start and end date for time-limited offers
